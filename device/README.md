# 장치 — 계속 새로 쓰는 장치 (BR-A 카드5)

리추얼 기록·출석·제출 현황 같은 입력 파일을 넣고 돌리면, 사이트에 쓸 숫자 칸(`output/site-data.json`)과
자기조절력·대인관계력·자기동기력 세 능력별 문단 후보(`output/candidates.json`)를 다시 만들어주는 장치입니다.

## 실행 방법 (3단계)

1. `device` 폴더를 아무 곳에나 복사합니다 (다른 파일 필요 없음, 이 폴더 하나로 완결).
2. 터미널에서 `device` 폴더로 이동해 아래 명령을 실행합니다.
   ```
   node generate.js
   ```
3. `output/site-data.json`과 `output/candidates.json`이 새로 만들어집니다. `output/candidates.json`을 읽고,
   사이트에 실제로 쓸 문장만 골라 `approved/approved.json`에 옮겨 적습니다 (이 파일은 장치가 절대 자동으로 건드리지 않습니다).

필요 조건: Node.js만 있으면 됩니다(버전 확인용으로 v24.19.0에서 테스트함, 외부 패키지 설치 없음 — `fs`/`path` 표준 모듈만 사용).

## AI 키

이 장치는 런타임에 AI를 호출하지 않습니다. 그래서 필요한 환경 변수도 없습니다. 문단 후보는 입력 데이터를
고정 규칙(키워드 매칭 + 템플릿)으로만 만들며, 실제 문장 다듬기는 사람이 `output/candidates.json`을 보고
`approved/approved.json`으로 옮기는 승인 과정에서 합니다. (AI 호출 결과를 그대로 넣으면 실행할 때마다
문구가 달라져 재현성이 깨지기 때문에, 이 설계에서는 처음부터 AI 호출을 배제했습니다.)

## 입력 파일 (`input/`)

- `ritual-history.json` — 리추얼 기록 원본 (출처: 제출자가 직접 다운로드한 `ritual-history-2026-09-22.json`)
- `attendance.json` — 출석 기록 (지각/조퇴/결석 횟수, 본인 구두 확인 값)
- `submissions.json` — 제출 현황 (완료/진행중 과제 목록, 날짜, 출처 경로 또는 URL)

새 기록이 생기면 이 세 파일을 최신 내용으로 바꾸고 `node generate.js`를 다시 실행하면 됩니다.

## 출력 파일 (`output/`)

- `site-data.json` — 사이트 "숫자 칸"에 쓸 값 (기록 일수, 기록 기간, 강점 일화 수, 상호 감사 언급 수, 지각/조퇴,
  완료 과제 수, SevMerge 커밋 수 등). 각 값에 어떤 입력 파일에서 나왔는지 `출처` 필드가 붙어 있습니다.
- `candidates.json` — 능력별 문단 후보 목록. 각 항목에 날짜, 원문 인용, 근거 위치(`source`)가 붙어 있습니다.
  이 파일은 참고용이며, 사이트에는 반영되지 않습니다.
- `재현성_확인.md` — 같은 입력으로 2회 실행한 결과 비교, 새 폴더에서 실행한 결과 기록.

## 재현성 원칙

`generate.js`는 무작위 값, 현재 시각(`Date.now()`), 외부 API 호출을 전혀 쓰지 않습니다. 모든 계산은
`input/` 안의 세 JSON 파일만 보고 결정되므로, 같은 입력이면 몇 번을 실행해도 바이트 단위로 같은 출력이
나옵니다. 검증 방법은 `output/재현성_확인.md`를 참고하세요.

## 승인 구조

`generate.js`는 `output/candidates.json`(후보)만 새로 쓰고, `approved/approved.json`(승인된 문장)은 절대
건드리지 않습니다. 사이트는 `approved/approved.json`에 있는 문장만 읽어서 씁니다. 그래서 후보가 아무리
많이 바뀌어도, 사람이 승인하기 전까지는 사이트 내용이 바뀌지 않습니다.
